Source Code and AGPL Notice

LocalPDFKit is being operated on an AGPL-compliant open-source route. This page explains how we handle corresponding source availability, upstream attribution, and the difference between LocalPDFKit brand assets and upstream project code.

Our Publication Route

LocalPDFKit follows an AGPL open-source route. For production deployment, the corresponding source for AGPL-covered website code should be available through a public repository or another clearly documented source distribution channel.

The public source repository for this deployment is published on GitHub. If you need help locating a specific revision or build, you can still contact us using the address below.

Upstream Attribution

LocalPDFKit is an independently branded website built from and around upstream open-source software, including BentoPDF and other third-party PDF libraries.

Original upstream licenses, notices, and attribution terms still apply to the code and components governed by those licenses.

What Source Availability Covers

  • Corresponding source for AGPL-covered code used in this site deployment
  • Notices and attribution relating to upstream open-source projects
  • LocalPDFKit-specific changes, page copy, and brand-facing site integration
  • A clear distinction between upstream software rights and LocalPDFKit brand assets

LocalPDFKit Brand Boundary

The LocalPDFKit name, domain, logo, social images, and original editorial copy are part of the LocalPDFKit brand unless a page explicitly states otherwise.

Open-source availability of code does not automatically grant the right to reuse LocalPDFKit trademarks or present another site as the official LocalPDFKit service.

Source Requests

If you cannot locate the published source materials or believe a notice is missing, email us with the deployed page URL, the build date if known, and the component you are asking about.
